## 试用发现与处理

1. **开发页白屏。** 首次真实浏览器访问出现 `Invalid hook call` 与 ConfigProvider 的 `useContext` 错误，日志显示开发依赖包与页面包中的 React 重复。已报告给 root；关闭开发 MFSU 后，页面可正常登录并执行上述流程。此发现与处理属于开发环境，不能据此推断原生产构建存在同样问题。
2. **查询按钮名称夹带装饰图标。** 查询按钮的可访问名称包含 `search`，不利于稳定识别。已给 TimeFilter 查询按钮明确的 `aria-label`，将装饰图标隐藏于辅助技术；后续真实查询成功。
3. **375px 抽屉向左裁切。** 固定 520/580/720 宽度的 Drawer 在窄屏显示不完整；仅检查 `document.scrollWidth` 没有发现负向越界。对初次截图的视觉复核发现标题和字段被裁切，因此当时不能报告手机验收通过。root 限制公共 Drawer 最大宽度后，学生和申请人的详情截图已复核完整。后续边界检查同时考虑 wrapper 的 `left`、`right` 与视口宽度。
4. **页面默认禁止缩放。** 实际 HTML 的 viewport 曾包含 `user-scalable=no` 和 `maximum-scale=1`。已报告给 root 并由其调整 Umi 配置；修复后读取实际页面元数据，已确认允许缩放。
5. **入场动画造成过早采样。** 一次新开查询抽屉的边界检查在滑入动画中间采到了位于屏幕右侧的 wrapper；这次失败不能据此认定最终布局仍有缺陷。复测脚本已改成等待入场完成再测，但后续因资源压力未完成，保留未验证状态。
