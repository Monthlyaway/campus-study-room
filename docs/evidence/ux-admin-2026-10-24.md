## 跨院系授权的手机保存

使用真实 API 创建仅用于本轮验收的独立账号，准备“计算机学院研习室”“人文学院阅览室”两条教室审批授权，然后：

1. 通过账号页面搜索这个账号并打开“设置职责”。
2. 核实已有两个教室都显示名称，职责弹窗不出现完整 UUID。
3. 打开教室选项，核实选项显示名称、知行楼及对应院系。
4. 切换到 375px，滚动至“保存授权”并点击，看到成功反馈。
5. 通过真实接口读回，两个 roomId 与原授权集合一致。
6. 停用本次新建的测试账号；未修改其他测试身份的职责。

初次复核发现 Ant Design 虚拟选择列表的辅助 option 文本仍含底层 UUID，虽然可见选项已经是名称。将每页只有 20 项的授权教室选择关闭虚拟列表后重跑，实际 option 文本为：

- 静思自习室 · 知行楼 · 全校共享
- 计算机学院研习室 · 知行楼 · 计算机学院
- 人文学院阅览室 · 知行楼 · 人文学院

复测保存成功，页面横向溢出为 0。最终记录为 output/playwright/admin-ux/authorization-save.json，截图为 cross-department-375.png；两次测试创建的独立账号均已停用。

## 独立代码复核

- 共享 useData 对查询路径隔离结果，避免切换页面条件时显示上一条查询的数据。
- App 的教室管理入口和路由都按 room:manage / user:manage 检查，并在页面内分开组织资料与业务管理；本人历史入口保留。
- M3 roomName 只在工单读权限或列表范围已通过后，通过 core HTTP 取得；同页按教室缓存，不直接读取 core 表。元数据失败不把工单显示为成功，也不扩大业务访问。
- 未发现以上 root 修改中的阻塞安全问题。正式 CI、发布版本校验和生产部署不属于本记录的已执行范围。
