# 身份、幂等、通知与期限任务

对应 REQ-D-03/D-06/D-07、REQ-X-01/X-03/X-06。业务记录通过 Spring Data JPA 保存；复杂权限投影、数据库分页和 PostgreSQL 行锁领取仍使用参数化查询。运行账号不执行 DDL。

## 写入与重放

用户写请求按账号、方法、规范路径和 UUID 幂等键串行化，同一事务保存业务效果与成功响应。成功记录至少保留24小时；相同内容重放返回原状态与data，不同内容409。业务异常回滚时不会占用成功键。内部资源/通知命令按commandId永久保存内容哈希与结果。

审计记录、通知和期限任务与业务写入同事务提交。审计区分 USER、SERVICE、JOB；运行账号仅有审计表INSERT/SELECT权限，实体同时标记为不可变。普通日志不得输出密码、会话、CSRF或签到码。

## 邮件与任务

通知按来源、事件、周期、接收人和通道去重。发送器每30秒领取到期或已过期租约记录，领取事务与SMTP发送分离，租约120秒。每次领取生成独立租约令牌；旧发送者不能覆盖新领取结果。发送失败前7次指数退避，第8次起持续每300秒重试并输出通用错误告警。已读时间与邮件送达状态独立；管理员重试复用原记录。

通知列表在数据库中按当前用户或管理范围过滤、计数与分页，管理端支持状态、来源和房间筛选。没有房间的系统通知仅ALL管理范围可见。维修通知只接受固定事件和模板字段，由core解析收件人；有效的必须收件人缺失时不消费命令。

期限任务持久化到PostgreSQL。每次执行重新取得任务/业务锁并检查当前状态；失败保留任务、次数和下一次尝试时间。停机恢复时先处理NO_SHOW，过时提醒不会补发。具体业务时间规则见[核心模块](core.md)。

共享会话cookie为`STUDYROOMSESSION`。停用或权限变更通过authVersion使两服务旧会话失效。教室每日签到码使用BCrypt校验与AES-GCM密文保存，部署迁移必须安全保留`checkin_key`；数据库备份不包含该密钥。

## 发布排空

`CONTROL_DIR/jobs-paused`阻止新后台工作。私有`/actuator/jobs`报告paused、active和activeRequests；公开Nginx拒绝所有`/actuator`和`/internal`路径。发布先开启维护，再确认两服务任务与业务请求均排空；超时不会强制继续迁移。

## 实际验证

2026-10-22，`python3 tests/integration/run_shared_persistence.py`在独立`studyroom_shared_integration`库执行7项测试，全部通过且无跳过；最终全仓集成后的再次验证也通过。覆盖：

- 通知去重，以及通知/审计同事务回滚；
- 过期租约旧发送者不能确认新任务，已读不取消发送；
- 8次失败持久退避与原记录手动重试；
- 8线程相同幂等键仅执行一次，失败后同键可重试；
- 审计数据库权限拒绝删除，JOB身份可区分；
- 通知权限、过滤及数据库分页；
- 独立事务保存登录/签到限流，时间窗后恢复。

真实SMTP使用本地Mailpit。正式外部SMTP收信按当前交付ADR延期，不将其视为已验证。尚未覆盖的完整停机补偿和全部业务组合，详见[需求追踪表](../requirements-traceability.md)。
