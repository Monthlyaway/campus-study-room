# 常见问题与恢复方法

[使用手册](README.md) · [常见工作流](workflows.md) · [业务页面](pages.md) · [管理工作台](administration.md)

先看页面提示和业务详情。一次点击发出请求，不等于已保存；同样，没收到邮件不等于业务失败。下面分别说明下一步。

<a id="uncertain"></a>
## “结果尚未确认”，该重新提交吗？

普通业务确认弹窗遇到网络中断，会提示“网络连接中断，结果尚未确认。请使用‘重试原请求’，不要重复新建。”保留弹窗和原内容，恢复网络后点“重试原请求”；不要改内容、关闭重开来当作同一次重试。成功后核对列表与业务编号。

如果已经关闭、刷新或退出导致原弹窗丢失，先检查“我的座位预约 / 我的申请 / 我的报修”，确认是否已有记录，再决定新建。原请求超过 24 小时时页面也会要求先检查业务记录。读取列表失败可以用“重试 / 刷新”，不会创建新业务。

“设置职责”保存授权遇到网络不确定时会锁定原内容，并提供“重试原请求”；超过 24 小时需先核对已生效的职责。“配置权限”“每周开放时间”仍使用独立保存弹窗：保留内容不变，重试同一个保存；若已离开，先重新打开核对现状。

<a id="conflict"></a>
## 提示“数据或资源已变化”（409）怎么办？

说明记录版本、座位占用或业务状态与刚才看到的不一致。普通业务弹窗会禁用提交按钮，提示“已刷新服务器数据，请返回后重新选择操作”；点“返回并重新选择”，核对刷新后的状态、时间、人员或资源，再选择新的合法动作。

“设置职责”也会停止提交旧授权并提示返回刷新。角色权限、开放时间弹窗：关闭弹窗，刷新所在列表或重新加载页面，再打开最新记录编辑。若之前有网络未确认，先核实上次是否已保存。不要连续提交旧页面，也不要把冲突一律理解为系统异常；最终审批资源冲突时，本次不留下批准，可以在截止前等资源可用后重试或驳回。

<a id="permission"></a>
## 菜单、标签或按钮不见了

先确认右上角登录者。菜单取决于当前权限；按钮还受本人/被派关系、院系/教室范围和业务状态限制。学生能预约座位，不代表有“申请教室”；系统管理员不自动能审批，维修人员只能处理派给自己的工单，实际维修人不能自验。

“教室与座位”内的校区、楼宇和院系由有账号管理权限的人员维护；教室和座位由有相应教室管理权限与范围的人员维护。页面只显示当前可办理的入口。

出现“无此操作权限”“暂无页面访问权限”（403）时联系管理员核对角色和范围，不借他人账号完成。管理员刚改授权时重新登录，再看菜单与记录。若提示安全令牌已过期，重新登录取得新的页面状态后重试合法动作。

## 登录突然失效，或记录显示不存在

提示登录失效（401）时重新登录。长时间未操作、登录已到最长时限，或账号/角色/范围/密码发生安全变更，都可能使原会话失效。已成功保存的业务不会因为重新登录而消失；登录后先查列表。

“记录不存在或不在你的访问范围”（404）也可能是权限隔离，而非记录已删除。确认环境、账号、完整业务编号和所选标签；请管理员核实，不尝试枚举其他人的编号。若是“没有找到这个页面”，用“回到首页”从真实菜单进入。

<a id="checkin"></a>
## 没有空位，或无法预约、取消、签到

| 情况 | 下一步 |
| --- | --- |
| 初次查找页没结果 | 先选日期、时间、时长，点“查询可预约座位” |
| 该时段没有空位 | 换时间，或清空过窄的教室/插座条件；院系准入、停用、未开放、整室占用和维修都可能排除座位 |
| 提示时间不合法 | 选将来的整点小时；结束在从现在起 14 天以内，不只看开始日期；不要跨越未开放时段 |
| 提示本人已有重叠预约 | 查看“我的座位预约”，选择不重叠时段；不同教室也不能重叠 |
| 开始后没有取消按钮 | 本人取消只限开始前；不能用取消绕开未签到 |
| 还没到开始时间 | 等到开始再“立即签到” |
| 编码校验失败 | 到正确教室核对当天屏幕编码；输入可忽略首尾空白及大小写，不能用昨日或别室的码 |
| 已到开始后 15 分钟 | 签到窗口已关闭，例如 09:15 不能为 09:00 开始的预约签到；查看最终状态 |
| “操作过于频繁”（429） | 停止连续点击，等待提示的时间窗后再试；签到每分钟最多 5 次尝试 |

“未签到记录”用于本人查看，当前不自动取消后续预约资格。维修导致的取消/中断不新增未签到违约；已经成立的未签到历史不因后来维修而删除。持有码只代表持有当日码，本系统不做定位签到。

<a id="sync"></a>
## 工单一直显示同步中，或者已完工仍不能预约

“正在暂停教室使用”表示资源确认前还不能视为维修开始；“待验收”继续下架；“正在恢复教室使用”表示验收已通过但尚未确认解除。只有“已完成”才能评价。验收超时不会自动通过或开放资源。

详情约 60 秒后停止自动刷新时，使用“刷新”查看，后台仍继续重试。出现“需要人工关注”请联系物业管理员，有权限者可“重试同步”；不要重复新建工单、要求手工改成关闭或清除失败记录。如果整个依赖服务不可用，用户动作可能直接显示“授权服务暂时不可用”，并非一定会保存成同步中；先查现有工单再决定重试。

即使某张工单已关闭，同室其他工单、整室申请、座位占用、未开放或停用仍可能阻止预约。维修前已取消的预约/申请不会恢复，要重新按正常流程申请可用资源。

## 邮件没收到，通知显示“待发送”

先看业务详情和“我的通知”。邮件未发送或重试中，不撤销成功业务；点“标记已读”也不会阻止邮件。默认本机邮件由 Mailpit 接收，收件箱地址见 [当前实例](../operations/current-instance.md)，其他安装询问维护者。

有权限人员在“邮件送达管理”按“待发送 / 发送中 / 重试中 / 已发送”筛选并重试原记录。“待发送”表示邮件尚未发出，“审批中”仅用于教室申请业务。连续失败 8 次后仍每 5 分钟重试，长期失败请提供该业务与请求编号给维护人员。

## 服务维护、保存失败或统计为空

出现“服务暂时不可用”（503）、维护页面或“暂时无法建立安全连接”，稍后用“重新连接 / 重试 / 刷新”。已经发起的写入如果结果不确定，按 [原请求恢复](#uncertain) 处理；不要不断新建。

字段报错时按提示修正必填项、长度、邮箱、时段或范围，再确认。角色与范围不能重复；父资源必须有效；仍有占用的资源不能靠强制停用跳过业务。开放时间与账号资料的具体限制见 [管理工作台](administration.md)。

统计“无数据”可能是没有达到签到截止的有效分母，不能改读成 0% 或 100%。先检查日期、教室与权限；一次最多查 31 天。空列表也可能是筛选太窄，先清筛选或换对应标签再刷新。

<a id="support"></a>
## 如何向维护人员描述问题？

提供系统入口或环境名称、页面/标签、操作时间（中国标准时间）、做了什么、预期与实际结果。附上提示中的请求编号，以及详情编号旁复制图标取得的完整预约/申请/工单编号；屏幕显示的八位前缀不够准确。

如需要截图，只截当前问题并遮去个人信息和签到码。不要发送密码、Cookie、内部凭证或他人的邮箱与明细。需要定位版本时，可附侧栏“版本”中的发布版本。说明是否出现过网络未确认、是否刷新/关闭弹窗、是否重试过，帮助维护者区分已保存与未完成。

提示语与恢复行为依据：[错误处理](../../apps/web/src/services/api.ts)、[业务弹窗](../../apps/web/src/components/business/common.tsx)。本页不承诺尚未实现的自助注册、支付、定位、上传照片或批量导出功能。
