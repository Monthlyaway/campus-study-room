# 栖学使用手册

栖学用于预约自习座位、申请整间教室、报修设施与管理校园空间。已有服务地址的使用者直接用浏览器打开，无需安装开发工具。首次使用先取得学校或环境维护者提供的地址与账号。

## 我想完成什么？

| 常见任务 | 从这里开始 | 完成后应看到什么 |
| --- | --- | --- |
| 预约座位、到场签到、再次预约 | [选座与签到](workflows.md#booking) | 预约从“待签到”变为“使用中”，到时为“已完成” |
| 申请整间教室并完成两级审批 | [申请与审批](workflows.md#application) | 两位独立审批人依次通过，申请为“已批准” |
| 报修、派单、维修、验收和评价 | [报修闭环](workflows.md#repair) | 确认恢复后“已关闭”，报修人可评价 |
| 给新成员开通申请或审批资格 | [开通账号与授权](workflows.md#accounts) | 保存授权后重新登录，出现正确入口和范围 |
| 添加教室座位、设置开放时间和签到屏 | [开放一间教室](workflows.md#spaces) | 新时段可查询；授权人员能打开教室签到屏 |
| 查询通知、处理未收信或提交结果不确定 | [通知与结果确认](workflows.md#notifications) | 找到业务真实状态；需要时重试原请求或原邮件 |

完整流程在 [常见工作流](workflows.md)，单页操作在 [页面指南](pages.md) 和 [管理工作台](administration.md)。已经遇到错误时，直接读 [常见问题](faq.md)。

## 第一次登录前

学校账号由管理员开通，忘记密码也联系管理员；登录页没有自助注册或邮件找回入口。只体验本地演示时，请查 [演示账号与环境说明](../development/demo-accounts.md)：该页统一维护 11 个账号的角色、样例资源，以及不同环境的密码取得方式。不要将某一环境的账号密码当成所有安装的通用值。

这台机器已安装的入口见 [当前本机实例](../operations/current-instance.md)。自己部署到新机器才需要 [安装指南](../operations/installation.md)。本手册的 `/seats` 等路径均相对于你正在使用的系统地址，不能把不同实例的地址混在一个流程中。

在登录页填“账号”“密码”，点击“登录”。进入的首页依当前权限而定；学生通常进入查找座位，审批员进入教室申请，系统管理员进入用户管理。默认学生身份没有整教室申请资格；系统管理员也不自动获得业务审批或维修资格。找不到菜单或动作，先确认登录身份、角色、数据范围与记录状态，再联系管理员。

## 导航与时间

桌面用左侧导航；手机用左上角“打开导航”。右上角铃铛进入通知中心，右上角姓名菜单可“退出登录”。切换演示角色时先退出，或使用相互隔离的浏览器配置；同一浏览器的普通标签页通常共用登录。管理表格可以在表格内部横向滚动查看右侧操作。

所有业务时间按中国标准时间 `Asia/Shanghai`。预约与整室申请按整点小时选择，开始必须晚于当前时刻，**结束时间**不能超过从提交时刻起未来 14 天；能选到第 14 天的日期，不保证该日任意结束时刻都合法。时长上限以页面选项为准，管理员调整只影响之后创建的业务。

列表中的编号通常只显示前八位，旁边的复制图标会复制完整编号。报障和审计查询使用复制出的完整值。侧栏底部“版本”可查看发布版本；无需把版本信息当作业务操作步骤。
