# 管理工作台

[使用手册](README.md) · [开通账号工作流](workflows.md#accounts) · [开放教室工作流](workflows.md#spaces) · [常见问题](faq.md)

以下六页从侧栏“管理工作台”打开。菜单由当前权限决定，记录和可执行动作还受数据范围限制。默认系统管理员负责账号/角色/参数/审计，空间管理员负责教室/座位，运营人员负责统计；需要组合职责时由获授权人员配置，不能只凭“管理员”名称操作所有页面。

<a id="users"></a>
## 用户管理

**入口：**“用户管理”，路径 `/admin/users`；需要账号管理权限，调整角色绑定还需要角色权限管理能力。

用“搜索账号或姓名”提交关键词，列表显示姓名/账号、邮箱、院系和启停状态，可分页、刷新。点“创建账号”填写以下资料，确认后列表出现新账号：

| 字段 | 要求 |
| --- | --- |
| 账号 | 必填，最多 64 字，使用学校分配的唯一账号 |
| 初始密码 | 12–64 个字符，UTF-8 不超过 72 字节；通过受控方式交给本人 |
| 姓名 | 必填，最多 64 字 |
| 邮箱 | 必填有效邮箱，最多 254 字，用于通知 |
| 所属院系 | 必选已启用院系；影响院系空间准入 |
| 学号（学生必填） | 计划授予学生角色时必须填写，最多 32 字 |

“编辑”修改姓名、邮箱和院系；当前编辑弹窗没有账号名、学号修改项。若创建时漏学号而需要学生身份，联系维护人员核实资料，不能按手册不存在的字段补改。“重置密码”要求输入新密码，旧会话失效；“停用”使其不能继续登录，历史仍保留，“启用”后可重新登录。系统拒绝移除最后一个有效系统管理员。

### 角色与数据范围

点“角色与范围”，弹窗标题为“角色与数据范围”。用“添加角色绑定”选角色，每个角色下“添加范围”，需要时移除对应角色或范围；最后“保存授权”。成功会提示“权限已更新，用户需重新登录”。

| 页面可选范围 | 怎样选择 |
| --- | --- |
| 本人 | 用于个人业务角色；不会让管理角色取得所有教室权限 |
| 指定院系 | 还需选择“院系”；例如院系审批员负责的申请人院系 |
| 指定教室 | 还需选择“教室”；例如空间审批员或空间管理员负责的教室 |
| 全校 | 该条绑定的权限覆盖全校，只授予确实需要此范围的人员 |

每条绑定的权限和范围一起生效，不能拿另一角色的“全校”范围扩展此角色。新增绑定默认“本人”，管理角色需要改成合适范围。当前页面只提供上表四种选择；已有特殊范围配置需要变更时联系维护者，不要用更大范围替代。

需要开通整室申请时，在已有学生绑定之外添加“教室申请人”；两级审批分配给不同人员。新建角色或保存授权不等于已验收用户能完成工作，应由本人重新登录核对入口与授权范围内业务。若保存提示版本冲突，关闭弹窗、刷新用户列表、重新打开后按最新授权调整；不要反复提交旧弹窗。

<a id="roles"></a>
## 角色权限

**入口：**“角色权限”，路径 `/admin/roles`；需要角色权限管理资格。

列表显示角色、编码、权限数量。点“新建角色”，填“角色编码”（最多 64 字）和“角色名称”（最多 100 字），确认后再对该角色点“配置权限”。勾选已有权限项并“保存”，应提示“角色权限已保存”，列表数量随之变化；最后去用户页绑定角色与范围。

角色名本身不会创建新能力，只有页面列出的权限可以授予。修改权限后关联用户需重新登录。系统管理员必须保留账号与权限管理能力；关键系统管理员角色或仍被用户关联的角色不能“停用”。先处理应当变更的用户绑定，不要通过删除历史或放宽保护绕过错误。

配置权限弹窗的按钮是“保存 / 取消”。遇版本冲突关闭弹窗，重新加载页面并打开最新角色；网络结果不确定时保留当前勾选内容重试同一保存，若已关闭则先重开查看是否已生效。普通创建/停用确认弹窗的处理见 [提交结果问题](faq.md#uncertain)。

<a id="spaces"></a>
## 空间管理

**入口：**“空间管理”，路径 `/admin/spaces`；需要空间管理权限。所有写入还受实际授权范围限制。页面有“教室与座位”“校区”“楼宇”；“院系”标签还要求账号管理权限，因此不保证默认单一系统管理员或空间管理员都能进入该子页。

### 校区、楼宇、院系

这三类资料的创建、编辑和启停都需要账号管理权限。通过当前空间页面操作时，还须有空间管理权限才能进入页面；默认 `room-admin` 看到校区/楼宇按钮不代表能保存，默认 `admin` 也没有空间页面入口。由获准同时具备两项权限的人员操作。

切换相应标签，点“添加校区 / 添加楼宇 / 添加院系”。填“编号”（最多 32 字）、“名称”（最多 100 字）；添加楼宇还要选所属校区。保存后列表显示新记录和状态。“编辑”只改名称，“停用 / 启用”修改状态；有启用资源或账号引用时会拒绝停用。

先建立并启用上级，再添加下级。界面不提供现有楼宇迁移校区、教室迁移楼宇或归属院系的操作；这类资料错误交由维护人员核实，不要靠改名称伪装迁移。

### 教室与座位

点“添加教室”，选择楼宇，填教室编号、名称；“所属院系（留空为全校共享）”决定公共或院系专属。保存后列表显示教室、位置、共享范围、座位数量和启停状态。选择该行“管理教室”进入详情。

| 详情入口 | 操作与结果 |
| --- | --- |
| 编辑名称 | 修改教室名称，确认后列表和详情更新；不更换编号或归属 |
| 开放时间 | 进入“每周开放时间”，配置完整开放区间，见下文 |
| 停用教室 / 启用教室 | 改变可用状态，保留历史；有效占用或封禁可能阻止停用 |
| 打开签到屏幕 | 有展示权限时出现；新标签页显示该教室当日码，见 [屏幕指南](pages.md#display) |
| 新增座位 | 填唯一座位编号，选有/无电源插座；保存后在座位表出现 |
| 座位行“插座” | 确认把当前插座标记切换为有或无 |
| 座位行“停用 / 启用” | 改座位状态；有效占用可能阻止停用，历史不会删除 |

新教室需有启用座位和开放时段才能在个人选座中出现，且查询者要有准入资格。仅添加名字不保证可约；请按 [开放教室工作流](workflows.md#spaces) 查询确认。

### 每周开放时间

点“添加开放区间”，逐项选择“星期”“开放开始”“开放结束”，必要时移除时间段，最后“保存”。成功提示“开放时间已更新”。结束必须晚于开始，起止按整点，同一天可有多个不重叠区间；跨午夜分成两天，例如周一 22:00–24:00、周二 00:00–02:00。

已有未来有效占用时不能修改；先查看占用并按原业务处理。保存失败留在弹窗，按字段提示修正；版本冲突则关闭开放时间和教室详情，刷新列表，重新打开再编辑。这里的保存弹窗不会显示普通业务的“返回并重新选择”。

### 资源占用记录

教室详情下方显示“个人预约 / 教室申请 / 维修封禁”的业务编号、开始、结束、状态，可“刷新”和分页。没有确定结束时间的封禁显示“恢复前持续”；状态为“生效中”或“已释放”。这是只读追溯入口，没有清除占用按钮。

无法停用或开放修改被拒时，从此处复制完整业务编号，交由有权处理该预约、申请或工单的人处理。一个来源释放不代表其他来源也释放；不能在空间页直接复活或删除业务。

<a id="config"></a>
## 系统参数

**入口：**“系统参数”，路径 `/admin/config`；需要参数管理权限。

页面显示“个人预约最长时长”“整教室申请最长时长”等卡片及当前小时数。点卡片“调整参数”，在“最长时长”选择 1–12 的整数小时并确认；成功后卡片显示新值。

新值只影响之后创建的预约或申请，不追溯缩短、取消旧记录。用户选择时长与提交之间若刚发生变更，应按服务端提示刷新后重新选。管理员遇到冲突，返回并读取当前参数，再决定是否仍要修改，不能反复提交旧值。

<a id="statistics"></a>
## 使用统计

**入口：**“使用统计”，路径 `/admin/statistics`；运营人员及有统计权限的人员，只看授权范围内数据。

选日期范围、可选教室，点击“刷新”取最新值；按中国标准时间自然日包含开始与结束日，单次最多 31 天。界面指标含义如下：

| 指标 | 如何理解 |
| --- | --- |
| 预约总数 | 预约开始时间落在所选日期范围内的记录数 |
| 签到率 | 仅对已经到签到截止、且未取消的预约，计算其中实际签到的比例；没有分母显示“无数据” |
| 预约座位时长 | 有效预约时段与查询日期的交集；未签到和取消不计，维修中断只计中断前时长 |
| 取消预约 | 所选范围中的取消记录数 |
| 未签到 | 所选范围中的未按时签到记录数 |

维修前已签到、后来中断的记录仍计入签到；维修导致的未签到取消不计入签到率。这里是“预约 / 签到记录指标”，不代表人员真实在场率。日期过长时缩短到最多 31 天；没有数据先检查时间、教室范围和业务记录，不把“无数据”解读为 100% 或系统故障。当前页面没有导出按钮。

<a id="audit"></a>
## 操作审计

**入口：**“操作审计”，路径 `/admin/audit`；需要审计查看权限。

先选“预约 / 审批 / 公共层”或“报修服务”，从业务详情的复制图标取得完整编号，粘贴到“按完整业务编号查询”后搜索。表格显示时间、动作、来源、对象、操作者、请求编号和原因，可刷新与分页；窄屏在表格内部横向滚动。

“对象”“操作者”“请求编号”可能只显示八位前缀，复制图标得到完整值。搜不到先检查业务类型标签、完整编号与权限，不把屏幕短编号当完整编号。所有记录只读；需要纠正业务，应回业务流程或联系对应负责人，不能在审计页修改历史。

维护依据：[Admin.tsx](../../apps/web/src/pages/Admin.tsx)、[中文角色与权限标签](../../apps/web/src/access.ts)。字段与业务约束以实际后端校验为准，保存失败时查看 [常见问题](faq.md)。
